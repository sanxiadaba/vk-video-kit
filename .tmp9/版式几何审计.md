# vk-video-kit · 版式与几何审计（1920×1080，23 帧）

## 0. 材料与口径

- 用当前 `src` 重建后重渲了 23 帧（`.tmp9/render/*.png`，780 版 `.tmp9/render780/*.png`）。
- 与 `out/showcase/frames/*.png` 逐像素比对：**15 帧完全一致**；8 帧不一致 —— `pair / term / canvas` 是几何差异（工作区未提交的 callout 曲线、引线长度、pair 轴线改动），`code-ring / code-fold / diff / tree / dark` 只是语法配色。所以下文数字取自**当前源码**，凡与出片不同会注明"出片"。
- 一句话结论：不是"某处该大一点"，是三条规则在互相打架 —— ①窗口/表格按内容宽（`max-content`），②标题与内容同处一个 `justify-content:center` 的栈，③线宽只有 3/4/7 却没有语义分工。

## 一、体系级问题（P0，影响多帧）

### 1. 标题垂直位置逐帧漂移 231px〔全部 23 帧〕
- 现象：同一个"标签+一句话"的标题块，在不同的帧里上下乱跑。
- 位置／尺寸：标签墨迹顶 y = 53( tree ) / 63( box-img ) / 80( compare ) / 93( code-ring, code-fold ) / 97( table ) / 108( layers ) / 121( diff ) / 133( asm ) / 168( timeline ) / 173( term ) / 213( cells ) / 224( list ) / 250( bits ) / 252( cover ) / 284( steps )。**极差 231px，780 宽下是 94px**（画面高度的 21%）。
- 根因：`.vk-stage{justify-content:center}`（base.css:56-64）＋ 标题与内容是同一条 flex 栈的孩子。标题的位置 = f(内容高度)，内容高度在 575(cover)~975(tree) 之间，于是标题被"居中"推着走。
- 建议规则：标题脱离内容流，做成固定带：`.vk-stage` 改 `flex-start`，标签顶锚定 y=96；标签行盒 80 + 32 + 标题行盒（subhead 120 / headline 176）= 标题块固定高 232/288；内容从 y=328/392 起，**只在剩余带内垂直居中**。验收口径：任意帧的标签墨迹顶必须 = 96±0。

### 2. 一半的帧没有用上版心，视觉重心整体左偏 340px〔23 帧〕
- 现象：右半个画面常年是空的，"小气/线短"的直接来源。
- 位置／尺寸：可见墨迹右边缘占 1800 的比例 —— table 53% / bits 52% / code-ring 56% / tree 58% / compare 60% / cover 63% / term 65% / list 67% / dark 72% / asm 73% / diff 73% / box-img 77% / bytes 81% / steps 87% / cells 88% / inline 91% / canvas 91% / timeline 93% / code-fold 97%；只有 bars、pair 100%。墨迹重心 x 偏移：−150( math ) ~ −539( tree )，**均值约 −340**（780 下 −138，整整偏出 1/6 屏）。
- 根因：三条各自为政的"按内容宽"规则 —— `.vk-win{width:max-content}`（components.css:236）、`vk-table table{width:auto}`（:492）、`vk-tree .vk-win{min-width:calc(var(--vk-safe-w)*0.46)}`（:580）。没有任何"帧级宽度"概念。
- 建议规则：引入 `--vk-block-w` 三档：`full 1680` / `two-thirds 1120` / `half 824`。窗口、表格、树、对比窗默认 `full`；收窄只有两种理由（并置、显式 `width="half"`）。验收口径：非并置帧的**最右可见边缘**必须落在 1800±4。

### 3. 代码字号被"自适应"改掉：同一 body 档渲染出 46.65 / 52.04 / 55.84 / 56 四种〔pair, dark, bytes, 其余〕
- 现象：pair 的代码明显比 code-fold 小一号，且窗口宽越窄字越小。
- 位置／尺寸：窗口宽 1624(code-fold, 56px) / 885(code-ring, 56) / 1382(bytes, 55.84) / 1046(term, 56) / 483(dark, **52.04**) / 802(pair, **46.65**)。780 下 22.7px vs 18.9px。
- 根因：`fitToBox()`（runtime/code.mjs:13-30）拿 `row.scrollWidth` 和 `win.clientWidth` 比，而窗口本身是 `max-content`，**need ≈ have 永远成立**，于是每次迭代都乘 `(have−6)/need`，收敛在比 56 小 0~17% 的值上；只有 `|Δ|<0.4` 才停，所以结果取决于巧合。
- 建议规则：宽度与字号解耦 —— 先由第 2 条定窗口宽，再二分字号；判断改 `if (need <= have) return;`，容差从 4px 提到 16px，比较对象用 `.vk-src` 的墨迹宽（不含行号列与内距），别用行盒 `scrollWidth`。

### 4. 5 帧越出版心：上边界最多上移 43px、下边界最多下移 43px〔tree, box-img, compare, code-ring, code-fold〕
- 位置／尺寸：版心是 120..1800 × 96..984。tree 墨迹 53..1027（左右各溢出 43）；box-img 63..1017（+33）；compare 80..1000（+16）；code-ring / code-fold 93..987（+3，安全区上下各被吃掉 3px）。
- 根因：容量只在构建期"提示不拦"（vocab.CAPACITY），运行期又用居中吸收溢出 —— 溢出被平分到上下，页边距从 96 缩到 53。
- 建议规则：`.vk-stage` 加 `overflow:hidden` + 自检硬失败（`audit` 里把"墨迹越出版心"从 warning 提到 error）；或给窗口类加 `max-height: calc(var(--vk-safe-h) - var(--vk-title-h))` 并让 `fitToBox` 在超出时缩字号。

### 5. 线宽三档在 0.406× 之后只剩两档可辨，且语义混乱〔全库〕
- 位置／尺寸：`--vk-line-w-hair 3` / `rule 4` / `strong 7`，780 下 = 1.2 / 1.6 / 2.8px。3 与 4 编码后不可分。7px 同时用于：窗口当前行条、callout 箭头、圈、注释引线、表头规则、格子当前框（box-shadow）；4px 同时用于：时间轴、pair 中轴、步骤章边框、注释框边框。
- 根因：只有"粗细"一个维度，没有"这根线在说什么"的维度；`hair` 与 `rule` 差 1px 是为了视觉，实际低于阈值。
- 建议规则：收到三档且语义唯一 —— `hair 4`（全部边框与行线）、`rule 8`（结构线：表头、时间轴、中轴、段分隔）、`strong 12`（只给"正在看这里"：箭头、圈、当前行条）。原来的 3 与 7 分别并入 4 和 12，中间不要只差 1px 的档；callout 引线从 7 降到 8。

### 6. 承重的结构线用了 10% 墨，780 下直接消失〔table, tree, cells, code 全部〕
- 位置／尺寸：`--vk-line-color = rgba(11,15,20,.10)` → 纸上等于 #e9e9ea。用它的有：表格行线 3px、树导线 3px、树横短线 39×3、格子边框 3px、代码 gutter 右分隔 3px、窗口头下沿 3px、bars 轨道。780 下 1.2px、亮度差 22/255 —— 视频一压就没了：tree 帧在 780 只剩缩进，table 帧只剩三行字。
- 根因：把"面的分界"（窗口头 vs 体，可有可无）和"结构线"（表格行、树层级、格子边界，必须有）塞进同一个 token。
- 建议规则：结构线一律 `--vk-line-strong`(32%)；10% 只留给"面与面之间"的分界。树导线/短横另给 4px + 40%。

### 7. 竖直节奏有三套：标签→标题、标题→内容 在 32 / 64 / 128 之间跳〔17 vs 5 vs 1 帧〕
- 位置／尺寸：标签盒底→标题盒顶 = 32（cover, inline, code-ring, code-fold, term, diff, asm, table, list, tree, bytes, pair, box-img, compare, layers, canvas, dark）/ 64（cells 293→357、bits 330→394、steps 364→428、timeline 248→312）/ 128（math 243→371）。标题→内容同规律：32 / 64 / 128（math 725→853）。
- 根因：`gap` 是作者属性（`gap="wide"` / `"section"`），标题块和内容共用同一个 gap，于是"语义相同的关系"被作者按帧改数值。
- 建议规则：标签→标题恒 32，标题→内容恒 64，**不许由 gap 属性改**；单件帧（math）允许 128，但必须在标题块内写死，不能借 stack gap。

## 二、单帧几何缺陷（P1）

### 8. canvas：箭头两端各打一个 250px 的回勾
- 位置／尺寸：`d = M616 589.25 C366.2 589.25 1006.2 739.25 1256 739.25`。起点 616 在盒子右边缘(640)**内侧 24px**；控制点 366 比起点还左 250px，另一端同理。路径包围盒 559..1256（应 616..1256）。
- 根因：`@side:left|right` 锚点解析成**零尺寸点**（rect.w=0），`_borderPoint` 退化成中心点；新加的 `normal()` 先判 `|p.x−rect.x| ≤ 1.5`，对零宽盒永远命中 → 永远返回 {−1,0}，控制点于是沿 −x 退 `bow`(=250)。
- 建议规则：side 锚点返回"边上的线段"（含 w/h），不要点；法线 = 从盒中心指向锚点的单位向量，不靠坐标嗅探；`bow = clamp(48, 0.35×弦长, 280)` 且**同号**（两端都沿 +x/或都沿法线外法向）。

### 9. term：注释引线是 64px／7px 的火柴棍，端点圆点骑在窗口边框上
- 位置／尺寸：引线 (1230,672)→(1166,672)，长 **64px**、粗 7px；圆点 r=9（18px）圆心正好落在窗口右边框 x=1166 上（窗口 120..1166），一半在窗内。note 盒 520×131。
- 780 下：26px 长、2.8px 粗、7.3px 点 —— 读成"一个疙瘩 + 一小段线"。
- 根因：`p2` 直接取 `ob.x+ob.w`（窗口边线），点又居中画在该点；引线长度 = gap（64），没有最小长度规则。
- 建议规则：引线端点外推 16px（点落在窗口外 16px）；引线长度 ≥ 96 且取 64 的整数倍；点 r=12 与线宽成 1.5:1；气泡—目标中心距 < 160 时不画线，只留点。

### 10. pair（出片）：中轴被 vs 牌的纸底切成两截，各 90px，间隙 72px
- 位置／尺寸：轴线 x=958..961（**4px**），`top:64 / bottom:64`；vs 牌 `background:var(--vk-paper)` 盖住中段 → 两段各 90px（546..635、708..797），间隙 72px；轴线总长 251px。轴线顶端 546 还扎进列标签行（482..562）16px。
- 根因：拿"底色遮线"当分隔；同时轴线从标签行内部开始（`top:var(--vk-gap-wide)` 相对整个 pair），所以上段天生短。
- 现状：工作区未提交改动（runtime/layout.mjs）已改成"有字就不画轴"，但规则层面仍缺"轴 = 两段"的定义。
- 建议规则：轴画成两段，8px 圆头，段长 ≥ 120：标签行下沿+16 → 符号上沿−24；符号下沿+24 → 窗口下沿。符号不遮罩。

### 11. steps：连接箭头飘在 348px 宽的 step 盒右缘，距前一个章 260px、距后一个章 32px
- 位置／尺寸：step 盒 348 宽、gap 96；章 88×88 贴在盒左；箭头（文字 `→`，61.6px）在 `left:100%` 处，实测 x=468..532；前一章右缘 208，后一章左缘 564。
- 根因：`.vk-step{flex:1 1 0}` 把盒子撑满，`::after` 挂在**盒子**的 100%，不是挂在章上；箭头又是文字字形（笔画约 3px），和 callout 的 7px svg 箭头不是一套。
- 建议规则：连接件贴在 `.vk-step-n` 上（`left:100% + 24px`），长度居中于两章之间、最小 64；箭头改用同一套 svg 符号（8px 线 + 40px 头），不用字形。

### 12. timeline：轴只铺到 1287（版心的 69%），末点悬在轴外
- 位置／尺寸：轴 120..1287（1167 长），第三个点 1283..1307（外径 24、环 4、内孔 16 露出纸底 → 轴线在点内断开 15px）。端环 24px = 780 下 9.7px。
- 根因：`.vk-tl-item:not(:last-child)::after{width:calc(100% + 64)}` 逐项画轴，最后一项不画；点的 `left:0` 与轴端同 x，轴止于点的左边缘。
- 建议规则：轴由容器画一条 120→1800 的整线（rule 8px），点用 paper 底 + 4px 环压在线上（外径 32）；最后一个点的圆心 = 1800 − 列宽/2。

### 13. table：表格只有 727px（43% 版心），caption 775px 比表格还宽
- 位置／尺寸：`vk-table` 元素 1680，内部 `table` **727**（120..847）；caption 墨迹 120..895；表头 7px 规则只走 727。
- 根因：`vk-table table{width:auto}`，列宽按内容，无列权重；caption 是块级，自然比 table 宽。
- 建议规则：`width:100%; table-layout:fixed` + 列权重（首列 1.2fr，数值列 1fr，末列右对齐到 1800）；caption 与表格同宽。

### 14. tree：`…还有更多` 行丢掉缩进和连接线，还被窗口左边框切掉
- 位置／尺寸：窗口头 `code/` 在 **223**，一级节点文字 **209**（比窗口头还左 14），二级 **304**，而 `is-more` 在 **123**（窗口内沿），无 `::before` 短横，墨迹 123..381。同帧缩进步长不等：123→209 是 **86**，209→304 是 **95**。
- 根因：`is-more` 作为 `.vk-tname-row` 的兄弟直接放在 `.vk-bd` 里，绕过了 `.vk-kids` 的缩进链；缩进步长由 `margin-left .55em + padding-left 1.1em + border 3px` 三段相加得出，和图标 1.25em 不同源。
- 建议规则：`is-more` 必须作为 child 行（缩进 = 同级、带短横），省略号用 `⋯` 不用 `……`；缩进改单一变量 `--vk-indent:88px`，各级严格累加。

### 15. bits：所谓"三段"只靠 24px 空隙，780 下是 10px
- 位置／尺寸：12 个位格，格 74×156、节距 67；段间只有 `margin-left:24px`（inset-lg）；整块墨迹 120..938（52% 宽）。780 下：格 30×63、段隙 10px、索引 19.5px。
- 根因：语义分组没有形状，只有间距；且间距档（24）比字距大不了一倍。
- 建议规则：段用结构线分：每段一条 8px 下划线（或 32px 顶部括线）+ 段名（符号/指数/尾数）落在线上；段隙 ≥ 64；位格宽 ≥ 1.5 倍值字宽，索引与值共用中心线。

### 16. cells：格子内距 12px，和全库面内距 32px 不是一个体系；指针胶囊贴顶 8px
- 位置／尺寸：`.vk-cell{padding:12}`，56px 的 `a[0]` 距边框 15px；胶囊 90×55、48px 字、压在上沿 −8px；标题→内容 64（其他帧 32）。
- 根因：`.vk-cell` 用了 `--vk-inset-md`，而窗口/盒子/注释都用 `--vk-gap-normal`；面内距没有统一 token。
- 建议规则：新增 `--vk-pad-surface:32`，所有"面"（box/win/cell/note）统一；胶囊抬到格顶 −24，或改成"4px 引线 + 24px 文字"。

### 17. box-img：右盒 66% 是空的，左盒图下多 117px —— 等高是 stretch 假象
- 位置／尺寸：左 967×689（图 897×504，盒内 621 高，图下留 **117**）；右 681×689（内容 234 高，下留 **455**）。
- 根因：`vk-grid` 默认 `align-items:stretch`，两个 `vk-box` 被拉平；盒内没有底对齐/均分规则。
- 建议规则：`vk-grid` 默认 `align-items:start`；要等高时显式 `align="stretch"` 并规定"内容底对齐"（多余高度由 padding-bottom 吸收），绝不允许"盒子等高、内容贴顶"。

### 18. compare：窗格固定高 559，16:9 的图在里面 823×463，上下各留 48px 灰带
- 位置／尺寸：`--vk-compare-h: calc(888*0.63)=559`，窗格 824 宽 → contain 后 824×463.5，letterbox 96px。
- 根因：窗格高按版心比例写死，不按窗格宽；而图是 16:9。
- 建议规则：窗格改 `aspect-ratio:16/9`（或高由宽推导），让图与窗格同比例；灰带消失两图才有可比性。

### 19. math：公式默认居中，比标题右移 345px
- 位置／尺寸：标签 120..232、caption 120..866，公式 **465..1471**（katex-display 居中，中心 968≈960）；公式顶 429，标签底 243 → 128 gap。
- 根因：`katex-display` 是块级 + 内部 `text-align:center` 的默认；没有"公式列"的左边界规则。
- 建议规则：`.katex-display{text-align:left}` 或给公式固定左边界 120（与正文同列）；display 公式上下留白用 64 不用 128。

### 20. bars：标签列被 `minmax(6em,auto)` 撑到 336，标签到条起点空 256px
- 位置／尺寸：标签墨迹 120..232，条轨 488..1555，值 1587..1800；两行条 96 间距（行高 80 + gap 16）。
- 根因：`grid-template-columns: minmax(6em, auto) 1fr auto` —— 6em=336 是**最小值**，而标签只有 112 宽，列宽按 336 走。
- 建议规则：`max-content 1fr auto`（或固定 4ch），条起点固定在 x=360，让所有帧条形起点共线。

### 21. code-ring：圈高 94 > 行距 80，挤进上下两行；内距 18×10 不对称
- 位置／尺寸：圈 rect 185,625 535×94，rx=28，stroke 7；被圈的行盒 632..712（80 高）；圈上下各侵入相邻行 7px。圈左缘 185 落在 125px 宽的 gutter 中间（gutter 123..248）。
- 根因：`padX=18 / padY=10` 硬编码（runtime/callout.mjs），没有和行高/字号的换算；rx 固定 28。
- 建议规则：pad 统一 12（上下左右同值）；圈高上限 = 行高 − 8（即 72），超出时只圈文字墨迹不圈行号；rx = 12。

### 22. "当前"有四种画法，跨帧不成体系〔asm, term, diff, cells, steps〕
- 位置／尺寸：asm/term = 7px 左侧内阴影 + 焦点淡底；diff = 整行底色（无条）；cells = 3px 边框 + 淡底 + 3px 外扩 box-shadow；steps = 章填充。
- 根因：每个件各写一遍"当前"，没有共享 `.is-current` 的表达式。
- 建议规则：一条 —— "当前 = 8px 焦点条 + 焦点淡底"；只有无法加条的形状（章、点、格子）才用填充，且填充必须同时带 8px 条或 8px 环。

## 三、体系级建议（会同时改多个组件）

1. **一条版心刻度**：所有可见件只允许三种宽度 `1680 / 1120 / 824`，只允许四个纵向锚点 `96 / 328 / 392 / 984`。窗口、表格、树、对比窗、条形图全部走同一刻度，验收脚本直接断言"最右可见边缘 = 1800±4、标签墨顶 = 96±0"。
2. **标题块脱离内容流**：`--vk-title-h`（232/288）成为 token，内容带在剩余高度里居中；容量超限由 `audit` 硬失败，而不是靠居中吸收溢出（对应问题 1、4、7）。
3. **线只有三档且语义唯一**：`4 边框 / 8 结构 / 12 焦点`；结构线一律 32% 墨，10% 墨只用于"面与面"的分界（对应问题 5、6）。
