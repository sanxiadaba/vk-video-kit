# 组件标本页审计（31 页）

审计对象：`http://127.0.0.1:8099/specimen/<tag>.html` 共 31 页（索引 001–031）。
审计方式：Playwright（Edge headless）逐页 `window.vk.ready()` 后截 1920×1080，另把每个状态带切成 1080 高的分块、并把首屏缩到 780×439 复核可读性。**31 页首屏、31 张状态带、10 张 780×439 复核图全部逐张看过**，本文所有结论都对应这些截图。
本轮只审不改：未改动任何组件、库、demo 与标本页，也未提交 git。

评分口径：每条 0/1/2，2 最好；总分 12。同分排序时按 ⑥ 观感 → ④ 真实 → ③ 可读 的严重程度排。
说明：③ 的判定基准是「整帧缩到 780×439」。库内 caption 有 48px 地板（=780 下 19.5px），所以**字号本身大多够**；真正在 780 下失效的是密度与标签（位号、格内小字、截图里的正文），不是字号地板。

## 2. 最差的 10 页

> 同分按 ⑥ → ④ → ③ 排序；第 9、10 名与另外 5 页同为 8 分，按「缺陷最硬」挑选（vk-timeline 有语义错误，vk-annotate 有越界）。

### 1）vk-page · 页面（5 分）
**为什么差**：它是一块 1920×1080 的画布，但标本里既没有画出安全区/边距，也没有任何内容，只有「示例页面 / 页面只提供 1920×1080 画布与安全区」这种自指文档句。①⑤ 都是 0：观众看到的是一行标题加一行小字，理解不到「画布」这个概念。
**怎么改（组件层）**：给 `vk-page` 一个默认关闭的 `guide` 层，能画出安全区框与 120 边距标注；示例换成真实的三段式开场（kicker + 标题 + 一句正文）。更彻底的做法是把它从「可展示组件」索引里拿掉，并入版面/画布说明。

### 2）vk-stack · 竖排（5 分）
**为什么差**：竖排是「看不见的能力」，三张 460px 宽的空卡（01/02/03）既没有真实内容，也不能说明 gap 与对齐；④ 是纯占位，⑤ 是 0——视频里没有人会「展示 stack」。
**怎么改（组件层）**：让 stack 的示例承担「版式契约」——用一条真实演算（小标题 + 一行代码 + 一行注释）三行叠放，并给 gap 两档并排对比；定位上把 stack 当 authoring primitive，只在 API 文档出现，不进标本索引。

### 3）vk-img · 图片（5 分）
**为什么差**：示例图 `sample.svg` 是白底线框示意图，没有边框、没有衬底，白图落在白纸上，第一眼完全看不出这是「图片」；`fit="cover"` 与 `radius="pill"` 两档会把图里的 `s[0]…s[5]` 文字直接裁断。①⑥ 都是 0。
**怎么改（组件层）**：换一张有明确边缘、有主体的真实图（截图或照片）；`vk-img` 内建「媒体衬底」（默认 1px 线或纸底）；`cover` 档补一个安全裁切参数（object-position 预设），避免裁断文字，并给 `contain` 档的留白一个浅底色。

### 4）vk-box · 面（6 分）
**为什么差**：6 档状态全是同一句「示例内容。这里只放一段中性占位文字。」重复，盒子被撑成约 1200×480 的空壳，留白比内容多 5 倍；「面」的能力（层级、底色、描边）没有内容来体现。④ 是 0。
**怎么改（组件层）**：用真实卡片内容（小标题 + 两行正文 + 一个数值）填充；状态只保留 `soft / paper / strong` 三档；box 本质是容器，建议不单独出标本，改成「容器」小节里的一张对比图。
### 5）vk-edge · 连线（6 分）
**为什么差**：页头在 1680 内放不下折成两行（「← 索引 · vk-edge · 连线」/「← vk-timeline vk-annotate → 028」），首屏第一眼就散；连线标签「指向」压在折线的拐点上，没有挖空背景。② 是 0：7 个箭头样式平铺，没有一个「该用哪种」的示范。
**怎么改（组件层）**：label 增加背景挖空（用画面底色描一圈，或加 pad），定位从「路径中点」改成「最长直线段中点」；标本页头改 flex-nowrap + 省略；状态带只留 solid / dashed / both 三档。

### 6）vk-note · 注解（6 分）
**为什么差**：31 页里最像「坏了」的一页——边注文本没有在卡片内换行，直接溢出到页面底色上（「明程序有没有跑完」悬在卡片外），编号徽标 ① 压在卡片边框上，引线只剩一个棕色小点，图例 ①② 与下方列表脱节。③ 是 0。
**怎么改（组件层）**：note 容器改成 block 布局 + `overflow-wrap:anywhere` + 明确 `max-width`，宽度按内容自适应而不是固定 `w="360"`；badge 与边框之间留 inset；引线从锚点真实边缘出发并做避让。

### 7）vk-label · 标签（7 分）
**为什么差**：一行里平铺 8 种标签（chip / badge / 三色 / anchored），锚定标签「你写的」与「通过」直接重叠成一团墨；② 是 0，观众看到的是属性大甩卖而不是「一个能力」。
**怎么改（组件层）**：给 `vk-label[for]` 内建避让——检测锚点的高度与相邻 label 的包围盒，自动 above/below 切换，且禁止与相邻标签重叠；标本首屏只留 chip + badge + 一个 anchored。

### 8）vk-bits · 位（7 分）
**为什么差**：32 个位号在 1680 里就已经两两相碰，缩到 780 连成「3130292827262524…」，③ 是 0；同时没有给出这串位对应的数值，学习者对不上「这到底是 1.0 还是 0.5」。④ 只有 1。
**怎么改（组件层）**：位号改「每 4 位标一次」或隔位省略，位格设最小宽度；增加 `index="sparse"` 档；右侧/下方补 `= 1.0` 的解码结果，并允许标出符号/指数/尾数三段的实际数值。

### 9）vk-timeline · 时间线（8 分，④0 ⑥0）
**为什么差**：内容是「事件一 / 说明一 / 事件三 / 说明三」的占位，1989 节点写着「52,980 · 预处理前 · 字节」——编译管线的数据被误植进年表；泳道档里 `52,980` 被折成「52,9 / 80」。另外 1972→1989（17 年）与 1989→1999（10 年）等距排布，却没有声明是等距轴，属于错误暗示。
**怎么改（组件层）**：节点按年份比例定位，或显式渲染「等距轴」标记；所有数值 token 加 `white-space:nowrap`；把节点文案换成真实计算机史事件（1972 C 语言 / 1989 …），并在数据契约定死「value 必须带单位」。

### 10）vk-annotate · 标注（8 分，⑥0 ③1）
**为什么差**：圈选椭圆比代码框还宽，压过行号、伸到框外；「编译」标签压在代码框右边缘；编号点「•2」漂到画面最右，和它标的「这里空着」脱节；气泡引线只剩一个点。缩到 780 后这些标注全糊在一起。
**怎么改（组件层）**：`circle` 的 bbox 以目标行 rect 为准并 clamp 在容器内（现在明显取了错误的容器宽度）；badge 用锚点元素右上角定位而不是整行/整帧；label 同样要背景挖空与碰撞避让。

## 3. 没必要的组件（⑤ = 0）

### vk-stack（竖排）
- 它在科普视频里解决什么：纵向排布与间距档位（`gap`），是作者写页面时的排版手段。
- 没有它行不行：**不行**——它是库的基础件，绝大多数版面都靠它；但它**不该作为「可展示组件」出现**。观众在视频里看到的是内容本身，看不到「一个 stack」。现在这页花了一整屏去展示一个不可见的能力，属于标本选题错误，不是组件错误。建议并入「版面/间距」说明，保留 API 文档即可。

### vk-page（页面）
- 它在科普视频里解决什么：提供 1920×1080 画布与 120 安全区，是所有镜头的底板。
- 没有它行不行：**不行**——整个库都建立在它上面；但「展示 vk-page」这件事本身没有意义（它就是你正在看的那块画布）。建议从 31 页索引里移除，改成「画布与安全区」的说明章节，配一张标了边距的示意图。

> 补充：`vk-canvas`（⑤=1）与 `vk-box`（⑤=1）也偏基建，但它们至少对应一个能看见的结果（绝对定位图 / 卡片），保留标本是合理的。

## 4. 共性问题（横跨多页）

### 4.1 首屏有效内容只占左上角，平均空掉 60%
`vk-text`、`vk-label`、`vk-inline`、`vk-stack`、`vk-layer`、`vk-pair`、`vk-steps`、`vk-timeline`、`vk-edge`、`vk-page`、`vk-canvas`、`vk-img` 这十几页，内容都钉在 1920×1080 的左上角，下面 60%–80% 是白；`vk-timeline` 甚至只用了左侧四分之一。
**库级改法**：把标本页的「帧板」从 top-left 舞台改成居中舞台（`vk-page` 默认 `align="center"`，或标本模板改成 1680×945 居中），并在评审门禁里加一条「有效内容 ≥ 画面 60%」。

### 4.2 占位文案成体系
`vk-box`（示例内容×6）、`vk-list`（条目一/二/三/四）、`vk-steps`（步骤一/二/三）、`vk-timeline`（事件一/说明一）、`vk-page`（示例页面）用的是同一类占位语，而且是同句重复。
**库级改法**：建一套共用示例语料（直接复用 `vk-code`/`vk-term`/`vk-diff` 里那套 hello.c 编译链 + 内存布局 + 真 bug），所有组件从同一份语料取内容；文案里禁止出现「示例 / 占位 / 条目 / 事件 / 步骤」，CI 加关键词拦截。

### 4.3 状态带 = 属性大甩卖，没有「推荐用法」
`vk-label` 7 档、`vk-edge` 7 档、`vk-grid` 6 档、`vk-list` 6 档、`vk-annotate` 6 档、`vk-box` 6 档，全部平铺，且没有一档被标成「主镜头」。
**库级改法**：每个组件定义「1 个主镜头 + ≤3 个状态」，其余档位进 `docs/reference` 的表格；标本页首屏只放主镜头，状态带默认折叠（或放到第二屏）。

### 4.4 容器测量/裁剪缺陷是同一类 bug
`vk-note` 文本溢出卡片、`vk-annotate` 圈选越界、`vk-edge` 页头折行、`vk-asm` 「执行」竖排、`vk-cells` 「char 1 字节」折行、`vk-timeline` 「52,980」折行、`vk-compare` 截图内容缩到 780 不可读——本质都是「容器宽度固定 / 缺少 nowrap 保护 / 没有 clamp」。
**库级改法**：给这些组件统一三条 CSS 契约（`min-width:0`、`overflow-wrap` 按需、`max-width:100%` + 内容自适应），文字 token 默认 `nowrap`，超宽走「缩略/省略」策略；CI 在 780 宽度跑一遍视觉回归。

### 4.5 数据语义与刻度不严谨
`vk-timeline` 把字节数塞进年表、`vk-bars` 用对数刻度却不写「对数刻度」（磁盘 1,000,000 与内存 120 相差 8000 多倍，画出来只差两倍半，且没标「对数刻度」）、`vk-bits` 不给解码值、`vk-compare` 左右两张截图的行不对齐。
**库级改法**：给数据型组件加「数据契约」并在渲染层兜底——timeline 的 value 单位必填、bars 的 `scale` 必填且渲染成刻度说明、bits 必须同时给 value 与解码文本、compare 支持按行号对齐并至少提供一句可读的 `alt`/摘要。

## 5. 结论摘要

- **最差 10 页**：vk-page(5)、vk-stack(5)、vk-img(5)、vk-box(6)、vk-edge(6)、vk-note(6)、vk-label(7)、vk-bits(7)、vk-timeline(8)、vk-annotate(8)。
- **最好 3 页**：vk-code(12)、vk-diff(12)、vk-term(11，11 分组里最接近可直接用于成片的一页；vk-inline / vk-flow / vk-bars 同为 11)。
- **最该先改的 3 个组件**：
  1. **vk-note** —— 文本直接溢出卡片，等于组件坏了；而「边注」是科普讲解里解释一行代码最高频的件。
  2. **vk-annotate** —— 圈选越界、编号点漂移、引线断头，「指着讲」是这类视频的核心动作，现在一用就露馅。
  3. **vk-label** —— 讲解里到处是「第 3 步 / 已完成 / 有洞」，锚定标签会互相压字，属于一用就出事故的件。
  （候补：**vk-timeline**，占位 + 语义错位，会直接把错误信息讲给观众。）
