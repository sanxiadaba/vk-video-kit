# 组件库减法审计 · 36 → 20

> 只写文档，没有删任何标签、没有改任何 API。删除是后续决定。
> 口径：`node bin/vk.mjs tags` 的 36 个标签全表；「用过」指在**这一集视频的真实页面**里用过
> （正片 `frames/01–09.html` 9 页 + 附录 `appendix.html`、`appendix-2.html`、`appendix-3.html` 3 页，共 12 页）。
> 标本页（`_site/specimens/` 37 个）36 个标签全用，所以"标本页用过"不算证据；`samples/` 是草稿，也不算。

## 0. 先正面回答那句质问

「组件库里的这么多组件是否真的有必要？为什么老是重复犯错？」

把 12 页逐页拆开数，答案是三个数字：

| 事实 | 数字 |
|---|---|
| 标签总数 | 36 |
| **只在一页里出现过**的标签 | **24 个**（inline icon img rule steps code term table tree bars cells bytes canvas edge math ring timeline window list diff compare bits asm pin） |
| 每页结构骨架真正在复用的标签 | 5 个（page stack text label grid） |

也就是说：**36 个标签里，24 个是"一页一次性器械"**。每做一页，作者就想找一个"更贴这个内容"的工具；
标签表只会做加法——每多一种内容形状就多一个标签。于是：

- **字多**：因为每个器械都自带"贴标签 / 挂说明"的槽位——`vk-flow` 的 `label`、`vk-pair` 的
  `vk-caption`、`vk-timeline` 的 `note`、`vk-note` 的边注、`vk-label` 的 kicker。工具在替你排版，
  它排出来的就是"标题 + 副题 + 说明 + 底注"四件套。同一句话（printf→call _puts）在
  `samples/sci4.html` 里被摊成 **9 段文字、中文 58 字、字号只有 36–112px**——不是作者想写这么多，
  是**工具的位置要求它写**。
- **字小**：因为字号是"内容优先"的档位（body 56 是正文档，不是观看档）。一页里塞进并置/图例/边注三样，
  每样只能分到半屏宽，`fit="width"` 一量，字就掉到 56–73。sci4 的代码 56.48px 就是这么来的。
- **不直观**：24 个器械只用一次，读者每次都在认新符号（这次是内存格，下次是位、再下次是字节窗）。
  一集 12 页总共用掉 **34 种标签，其中 24 种只用了一次**——没有任何一种被反复用到形成"视觉语法"。
- **套模板**：因为有 36 个槽位，"每页都要有页眉 + 标题 + 副题 + 底注"变成了默认；减法反而要额外功。
- **打补丁**：需求 → 新标签，是最省事的一步（`vk-compare`、`vk-diff`、`vk-asm`、`vk-bits` 都是这么长出来的）。
  补丁也会长在属性上：`fit` 量宽失效，就在页里写 `fit-max="73.3"` / `"69.5"` 硬钉字号——那是补丁的补丁。

**根因不是"组件太多"，是"没有预算"。** 库只判客观错误（溢出/对比度/安全区），从不过问
"这页该有几个字、多大字、几件东西"。没有预算，作者就只能靠加组件来表达；组件越多，页面越满。

所以这份审计的结论不是"删 16 个标签"就完了，而是三件事：
**砍掉一次性器械 → 留 20 个 → 给剩下的立预算（见 §4）。**

## 2. 压到 20 个：删 / 合并 16 条

一行一条，括号里是替代路径：

1. `vk-annotate`（删除——12 页 0 次，只有标本页用；arrow→edge、circle→ring、note/badge→note）
2. `vk-flow`（删除——正片 0 次；两段→pair，多段→steps）
3. `vk-canvas`（删除——只有 08 用，5 个属性换绝对定位；改成一格一物）
4. `vk-window`（合并到 `vk-panel`）
5. `vk-icon`（合并到 `vk-text`）
6. `vk-rule`（合并到 `vk-box` 的 `border="hair"`）
7. `vk-caption`（合并到 `vk-label ink="tertiary"`）
8. `vk-pin`（合并到 `vk-note kind="legend"`）
9. `vk-ring`（合并到 `vk-box tone="focus" border="strong"`）
10. `vk-diff`（合并到 `vk-code` 两窗 + 行 mark）
11. `vk-compare`（合并到 `vk-pair` + 两张 `vk-img`）
12. `vk-cells`（合并到 `vk-grid` + `vk-box`）
13. `vk-bits`（合并到 `vk-cells`，最终落到 `vk-grid`）
14. `vk-bars`（合并到 `vk-table`）

## 4. 不删标签，先立四条预算（这才是防复发的闸门）

删标签只解决"工具箱太大"，不解决"作者还是想写满"。四条预算要在**页面**这一侧收：

| 预算 | 硬线 | 为什么 |
|---|---|---|
| 文字 | 全页中文 ≤ 12 字（标题算在内） | 字数一多，字必然小：字多了就要挤进同一块安全区 |
| 字号 | 主体 ≥ 120px | 手机横屏 0.406× 下，120px 只剩 49px；56px 只剩 23px——那是"注释"，不是"画面" |
| 元素 | 一页 ≤ 3 个视觉元素 | 两块内容 + 一个箭头，或一块 + 一句话 + 一个数字 |
| 器械 | 一页 ≤ 1 个 L3 器械 | 一页同时出现 code/term/table 两张，读者就要同时学两套符号 |

建议落成两个可选闸门（默认不跑，和 `--style` 同一层）：
`vk check --budget`：读页面上的可见文字总数与最小主体字号，超预算报 `warn`；
`vk doc --core`：只列 §3 的 12 个，其余标「实验·不进核心」。

## 5. 样板：`samples/sci5.html`

同一句话（printf 被换成 `call _puts`），旧做法 vs 减法：

| | sci4（旧） | sci5（减） |
|---|---|---|
| 可见文字 | 9 段，中文 **58 字**，可见字符 97 | 3 段，中文 **0 字**，可见字符 **16** |
| 主体字号 | 代码 56.48px（左）/ 101.67px（右），最小 36px | **200px / 200px**（两块一样大，全页最小 200px） |
| 视觉元素 | 9 段文字 + 2 个色块 + 1 条细箭头 | **3**（灰面 + 钴蓝箭头 + 绿面） |
| 用到的标签 | 5 个（page stack label text flow） | **4 个**（page stack box text） |
| 页内 CSS | 0 行 | 0 行（零 `<style>`、零内联；只引库的两张 CSS） |

sci5 = 灰面（`vk-box surface="sf-1"`）里一行 `printf`，钴蓝 `↓`（`vk-text tone="focus"`），
绿面（`vk-box tone="ok"`）里一行 `call _puts`。没有标题、没有说明、没有页眉——
`printf` 在上、`call _puts` 在下，箭头在中间，画面自己说完。
