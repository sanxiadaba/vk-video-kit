# vk 设计说明

> 这不是规范手册，是这套画面为什么长这样的解释。规则只有一条：
> **观众在手机横屏上要读得懂。**

## 1 · 观看条件

1920×1080 出片，手机横屏播放时约 **0.333×**。所有尺寸都是设计像素；排版按手机可读性定，但画布只有一个。

判定一句：**观众需要读它才能看懂吗？**

- 需要 → 正文 **52**（手机约 1/3 时 17.3px）
- 只是标签 / 表头 / 次级 → **48**（16px）
- 只是定位，不读也不影响理解 → **44**（14.7px）

44 是地板。行号、文件名、角标、页脚这类“有它更好、没它也能懂”的字，也只到 44。构建期门禁会在 1920 画布上查这条线；手机端约 1/3 的观看效果按同一比例验收。

公式是唯一的排版例外：主体跟正文（52 / 48），KaTeX 的上下标按 0.7em 缩放；不为了凑 44 把整个公式放大到破坏版面。

## 2 · 两条铁律

### 焦点只有一个颜色：冷钴蓝

强调不是"再加一个前景色"，而是**把这一块刷亮**：整行代码、标题里的关键词、当前步骤。冷钴蓝 `--vk-focus` 只做底，字仍然是墨色。

代码关键字回到墨色，靠字重区分。蓝只表示"看这里"。

### 语义色不写正文

对 / 错 / 注意只出现在三种地方：**色条、底色、图标**。正文永远是墨色。

原因是代码语法已经占用了整套色相：字符串是绿的、数字是琥珀的、函数是紫的。如果"对"也是绿的，观众会同时看到"这是字符串"和"这是安全的"，两个意思被压进一个颜色。

## 3 · 字阶

| 角色 | 值 | 手机约 1/3 |
|---|---|---|
| 金句 | 120 | 40 |
| 页标题 | 88 | 29.3 |
| 小标题 | 64 | 21.3 |
| 正文 / 讲解 | 52 | 17.3 |
| 标签 / 表头 / 次级 | 48 | 16 |
| 元信息 / 行号 | 44 | 14.7 |
| 代码 | 48 / 56 | 16 / 18.7 |
| 行旁批注 | 52 | 17.3 |

字重只有 400 / 500 / 700。中文在 500 与 600 之间会触发合成加粗，笔画会糊。

行高：大字 1.1，小标题 1.25，正文 1.5，代码 1.45，批注 1.3。≥72 的标题收字距 `-0.03em`，等宽小字放 `0.04em`。

展示站界面（导航、属性表、代码块）用网页字号 **12–36**；它和视频画面是两套尺度，不互相借字号。

## 4 · 间距

8 的倍数，三档就够：

| 场合 | 值 |
|---|---|
| 组件内部 | 8 / 16 / 24 |
| 内容块之间 | 24 / 32 / 48 / 64 |
| 页面安全区 | 左右 120、上下 96 |

节奏靠布局的 `gap` 和容器的 `padding`。`margin` 只用于把某样东西推开（例如 `mt-auto`），不用来制造节奏。

一屏 1680×888。字变大以后，**一屏只讲一个点**；代码带标题约 9 行，纯代码约 12 行。

## 5 · 窗与材质

全库只有一个窗：`.vk-win`（L1 造型原语，不是标签）。代码、终端、diff、图窗、浏览器都只是往窗里填内容。

- **paper**：白底。默认给代码窗、diff、图窗。
- **ink**：深底。终端默认 ink；代码窗要深色时写 `surface="ink"`。
- 同屏可以一深一浅——真实工具就是编辑器浅、终端深。

标题栏 80：三点 18px（红 / 黄 / 绿）、文件名做成 44px 的 tab、语言角标 44px。三点只在 `chrome=min` 出现；它只说明"这是一个窗口"，不表达状态。没有第二个"窗口点"，没有调试页脚。

## 6 · 代码、终端、diff

### 代码：真实文件是唯一真相

- `src="code/hello.c"` 指向真实源文件，`lines="12-18"` 选行段。
- `src` 是作者唯一要写的引用；构建期把读到的源码放进 `data-vk-src` 机器数据，HTML 里不出现第二份手敲源码。终端 / 文件树 / 公式同理：`src` 分别指向 transcript、真实目录、`.tex`。
- 行号按**片段**从 1 起；`highlight` / `focus` / `fold` 也是片段里的 1-based 行。
- 构建期用 Shiki 高亮，运行时零依赖。
- 代码 48（默认）/ 56（`density="large"`，主镜头），行高 1.45；行号 44、`ink-4`、等宽数字，槽宽 72（三位数 96）。
- 整行高亮：冷蓝底 + 左侧 4px 色条，色条画在 gutter 外，行内容不位移。
- 聚光：其余行退到 **0.28**，不是 0.84。
- 缺口：中间插一行"⋯ 中间省略"，不假装连续。

### 终端：一行一个状态

- 默认深色。命令行 `$`，输出无前缀，结果行用**显式前缀**：`✓` / `!` / `✗`。
- 结果行整行有很淡的语义底，glyph 让色盲也能读；正文仍是墨色。
- 光标是**块**（约 0.62em × 1.15em），不是 3px 竖线；`data-vk-motion="off"` 时冻在常亮。
- 不编造输出。"✓ build ok" 这类不是真实工具输出的东西，不进示例。

### diff：默认上下对照，可并排

- 默认改前一行、改后一行，从上往下读；三种信号同时成立：行首 `−` / `+`、左侧 4px 色条、改动词的 3px 下划线。
- `variant="split"` 换成左右两窗并排：改前 / 改后各一窗，行数一一对应，空行留白；每列代码退到 44 地板以容纳 24 个字符。
- 顶部只有一句 `N 行改动`；上下文行保持原样，不抢焦点。
- 改动用 token LCS，`<=` 与 `<` 都会各自成为改动区间；词级字符 LCS 不再使用。
- `summary="none"` 关计数，`chrome="none"` 去窗头。

## 7 · 批注

`vk-annotate` 是**行旁批注**，不是编号图例。

- 批注贴在代码行右侧，按行心对齐；关系由"对齐"表达，不画长引线。
- 只有 `for="#id"` 指向非代码元素时，才画一条短正交引线：2px、圆点在目标上、不出安全区。
- 一条批注 = 一个意思。最多两行；超过就把意思拆成两条，不缩字。
- `n` 是可选的多步编号，默认不出现。

曲线不提供：手机横屏约 1/3 时分辨不出曲率，只会制造歧义。

## 8 · 层

```
L0 值       色 / 字 / 间 / 形 / 线 / 动
L1 元素     面 · 字 · 图标 · 图 · 线 · 标记（6 个标签 + .vk-win 窗壳）
L2 布局     竖排 · 横排 · 网格 · 坐标系 · 连线
L3 组件     标题 · 列表 · 标签 · 提示框 · 代码 · 终端 · diff · 表格 · 公式 · 图窗 · 浏览器 · 文件树 · 键位 · 内存格 · 步骤 · 进度
L4 装置     页面 · 行旁批注 · 讲解条
```

`vk-page` 是画布工具（安全区 + 缩放 + 可选页眉页脚），不占元件位。

每一层只做一件事：

- **L0** 只放值。
- **L1** 只画一个物件；不认识兄弟，不排版。`.vk-win` 是这一层的窗壳原语。
- **L2** 只决定在哪、多大。
- **L3** 只写"这类内容怎么读"：行节奏、语法色、diff 三通道、表格列宽。窗壳来自 L1。
- **L4** 只组织多个组件和跨组件几何，不改下层外观。

时间轴不在这里。库保证"静止帧就是成品"；什么时候出现、怎么动，是编排层的事。

## 9 · 展示站

展示站不是模板墙，也不是一张张成品截图。

- 首页先看 8 帧；每帧能全幅打开，也能复制它的 recipe。
- **组件索引**按 L1–L4 找；每个组件一页：16:9 预览 + preset tabs + 源码 + 属性表 + 设计说明。
- 预览是真实 `specimens/<tag>.html` 的 iframe，不是另做一套 demo；preset tab 直接改 iframe 里的属性，再调用 `vk.layout()`。
- 预设是"看得见的另一面"：用 `npm run gate:visual` 逐张对比像素差异；空操作、引用不存在的属性会被提前拦下。
- 属性从 registry 自动生成；有中文名、类型、默认值；布尔是复选框，枚举是下拉。
- 「复制」复制的是当前变体的 HTML 片段；片段里的 `src` 仍指向真实文件，粘到新页面后要跑 `npx vk build`（或 dev server）预编译。
- `docs.html` 一个 H1 + 左 TOC；`examples.html` 是 8 帧索引。
- 桌面 only；不提供移动布局，也不做组件属性自由面板。

## 10 · 一帧一个焦点

如果你有两个东西都想让人看，那是两帧。

内容装不下时，删内容，不缩字。这是这套库唯一愿意坚持的"约束"。

## 11 · 动效边界

库只描述"动起来是什么样"：`data-reveal` 逐行淡入、`data-type` 逐行打字、块状光标。

- `vk.freeze()` / `<html data-vk-motion="off">` 冻在终态，截图和录首帧是同一张画面。
- 时长与顺序由编排层给；库里没有播放器，也没有时间轴。
