# vk 设计说明

> 这不是规范手册，是这套画面为什么长这样的解释。规则只有一条：
> **观众在手机横屏上要读得懂。**

## 1 · 观看条件

1920×1080 出片，手机横屏播放时约 **0.333×**。所有尺寸都是设计像素；排版按手机可读性定，但画布只有一个。

判定一句：**观众需要读它才能看懂吗？**

- 需要读懂 → 正文 **52**（手机约 1/3 时 17.3px）
- 只是标签 / 表头 / 元数据 / 密集 ASCII 数据 → **40**（13.3px）

**两个门槛，五档。** 52 是"要读懂的内容"，40 是"元数据、标签、密集 ASCII 数据"。中间不再有 44 与 48——它们只差 4px，在手机上根本是同一档。任何可读文字不得低于 40；`[data-meta]` 标记元数据，门禁按"含汉字且长于 12 字"判定一整句是不是被排小了。

等宽 ASCII 可以用 40 承载内容：它的 x-height 比汉字大，40 的等宽数字可读性约等于 52 的汉字。所以 `vk-asm` / `vk-bytes` / `vk-bits` 的机器码、十六进制、位串都在 40。

公式是唯一的排版例外：主体跟正文（52），KaTeX 的上下标按 0.7em 缩放；不为了凑档位把整个公式放大到破坏版面。

## 2 · 两条铁律

### 钴蓝只做一件事：标出"正在讲这里"

强调不是"再加一堆前景色"，而是**把该亮的地方刷亮**。全库只有当前行 / 当前格 / 当前这一块有蓝：整行 16% 蓝底 + 左侧 4px 实心蓝条。

语法不参与蓝色。关键字与数字都用墨色 600，函数也是墨色 600，语法色只剩字符串的绿和注释的灰。这样观众扫一眼代码，蓝色出现的地方就是你要讲的地方。

### 语义色不写正文

对 / 错 / 注意只出现在三种地方：**色条、底色、图标**。正文永远是墨色。

原因是代码语法已经占用了色相：字符串是绿的。如果"对"也是绿的，观众会同时看到"这是字符串"和"这是安全的"，两个意思被压进一个颜色。琥珀只留给"注意"这一件事，数字已经回到墨阶。

## 3 · 字阶

| 角色 | 值 | 手机约 1/3 |
|---|---|---|
| 金句 | `display` 120 | 40 |
| 页标题 | `title` 88 | 29.3 |
| 小标题 | `heading` 64 | 21.3 |
| 正文 / 讲解 / 代码 | `body` 52 | 17.3 |
| 标签 / 表头 / 元数据 / 密集 ASCII | `meta` 40 | 13.3 |

五档就是全部。`size` 只接受这五个名字，组件声明自己支持哪几档，写别的会在构建期报错。

字重只有 400 / 500 / 700。中文 500 与 700 都是真字重（Noto Sans SC 的 500/700 分片随包），不靠合成加粗。

行高：大字 1.1，小标题 1.25，正文 1.5，代码 1.45，批注 1.3。≥72 的标题收字距 `-0.03em`，等宽小字放 `0.04em`。

规格页也是帧：索引与每个组件页都长在 1920×1080 里。内容 52，元数据 40。

## 4 · 间距

8 的倍数，三档就够：

| 场合 | 值 |
|---|---|
| 组件内部 | 8 / 16 / 24 |
| 内容块之间 | 24 / 32 / 48 / 64 |
| 页面安全区 | 左右 120、上下 96 |

节奏靠布局的 `gap` 和容器的 `padding`。`margin` 只用于把某样东西推开（例如 `mt-auto`），不用来制造节奏。

一屏 1680×888。字变大以后，**一屏只讲一个点**；代码带标题约 9 行，纯代码约 12 行。

## 5 · 窗与材质

全库只有一个窗：`.vk-win`（L1 造型原语，`vk-window` 是它的公开标签）。代码、终端、diff、图窗、地址栏都只是往窗里填内容。

- **只有白纸**：窗、代码、终端、diff、图窗全部是白底。没有深色主题，没有 `surface="ink"`。
- 浅灰 `#f6f8fb` 只用于窗头、表头、斑马行、提示块，是同一张纸上的分区，不是第二种材质。

标题栏 56：三点 + 文件名 40（mono，500）做成 48 高圆角 tag + 行段 28；右侧语言角标 40；一条 1px 分隔线。不是假 tab，也不是 IDE 截图。

提示框（callout）是两栏：图标一列，标题与正文同处右栏；标题 = 正文升一档（meta 40→52、body 52→64、heading 64→88），图标与标题首行对齐，标题换行不把图标推到两行中间。

## 6 · 代码、终端、diff

### 代码：真实文件优先，也可内联

- `src="code/hello.c"` 指向真实源文件，`lines="12-18"` 选行段。
- 短代码可以直接放进 `<script type="text/plain" data-vk-source>`；浏览器不解析块里的 `<`，构建期照样高亮。`src` 与内联块只能有一个。
- `src` 是长文件的首选；构建期把读到的源码放进 `data-vk-src` 机器数据，HTML 里不出现第二份手敲源码。终端 / 文件树 / 公式 / 汇编同理。
- 行号默认按**源文件**行号（`lines="4-6"` 时 gutter 是 4/5/6）；`numbering="slice"` 才回到 1 起。`current` / `focus` / `fold` 仍按片段行。
- 构建期用 Shiki 高亮，运行时零依赖。
- 代码 52，行高 1.45；行号 40、`ink-4`、等宽数字，无底色/无阴影；代码与行号都从窗头内距（32）开始。`density` 只改行高与留白，不改字号——放大字是 `size` 的事，不是密度的事。
- 当前行：整行 16% 冷蓝、代码左侧 4px 蓝线、行号变蓝加粗；不是一整块色条。
- 聚光：其余行退到 **0.28**，不是 0.84。
- 缺口：中间插一行"⋯ 中间省略"，不假装连续。

### 汇编：地址、机器码、指令三列

- `vk-asm` 接受 objdump 文本或普通 `.s`；地址列可以关，机器码列用 `bytes` 打开。
- 每行同时带 `data-line` 与 `data-addr`，`vk-edge` 可以从 C 的某一行直接连到汇编的某一条指令。
- 没有地址/机器码时退化为普通指令清单，不编造列。

### 终端：一行一个状态

- 默认白底，与代码窗一致；全库没有深色窗。命令行 `$`，输出无前缀，结果行用**显式前缀**：`✓` / `!` / `✗`。
- 结果行整行有很淡的语义底，glyph 让色盲也能读；正文仍是墨色。
- 不编造输出。"✓ build ok" 这类不是真实工具输出的东西，不进示例。

### diff：默认上下对照，可并排

- 默认改前一行、改后一行，从上往下读；三种信号同时成立：行首 `−` / `+`、左侧 4px 色条、改动词的 3px 下划线。
- `variant="split"` 换成左右两窗并排：改前 / 改后各一窗，行数一一对应，空行留白；每列代码用 40（密集 ASCII 档）以容纳 24 个字符。
- 顶部只有一句 `N 行改动`；上下文行保持原样，不抢焦点。
- 改动用 token LCS，`<=` 与 `<` 都会各自成为改动区间；词级字符 LCS 不再使用。
- `summary="none"` 关计数，`chrome="none"` 去窗头。

## 7 · 关系覆盖层

图里的指认用覆盖层，不挤进内容流：

- `vk-ring`：圈选/框选/下划线，只描边，不改目标尺寸；默认焦点色，红只给错误。
- `vk-spotlight`：除目标外用白色淡出，目标保持原色并加焦点描边；全库没有黑色遮罩。
- `vk-pin`：气泡 + 引线，自动找空位，也可以写死 `x` / `y`。

三者都读 `for="#id@part:arg"`，多个目标用分号隔开（region 自己要用逗号）；隐藏镜头里不画。

## 8 · 层

```
L0 值       色 / 字 / 间 / 形 / 线
L1 原子     面 · 字 · 行内 · 图标 · 图 · 线 · 标记 · 窗 · 键位（9 个标签 + .vk-win 窗壳）
L2 排布     竖排 · 横排 · 网格 · 坐标系（4）
L3 器械     标题 · 列表 · 标签 · 提示框 · 代码 · 终端 · diff · 表格 · 公式 · 图窗 · 树 · 内存格 · 字节 · 步骤 · 引文 · 位 · 条 · 汇编 · 时间线（19）
L4 关系     连线 · 批注泡 · 圈选 · 聚光（4）
L5 页面     页面（1）
```

`vk-page` 是画布工具（1920×1080 + 安全区 + 对齐），不缩放、不含页眉页脚；它单独一层，因为它决定的是“一张画面”而不是“画面里的一个东西”。

每一层只做一件事：

- **L0** 只放值。
- **L1** 只画一个物件；不认识兄弟，不排版。`.vk-win` 是这一层的窗壳原语。
- **L2** 只决定在哪、多大。
- **L3** 只渲染一种编程数据的形状：行节奏、语法色、diff 三通道、表格列宽、字节地址、树层级、汇编列、时间轴刻度。窗壳来自 L1。
- **L4** 只表达两个东西之间的关系与批注，不改下层的形状；圈选、聚光、气泡都只画覆盖层。
- **L5** 只给整张帧一个画布。

时间轴不在这里。库保证"静止帧就是成品"；什么时候出现、怎么动，是编排层的事。

## 9 · 规格页

文档不是模板墙，也不是成品截图；它是 37 张用库自己排的规格页。

- **索引**是帧，分 7 页：前 6 页每页 6 格（3 列 × 2 行），最后一页 1 格；每格是整张标本页的等比缩略图 + 名字 + `vk-*` 标签名。缩略图只裁上方 1080 帧板，所以"索引里看到的"与"点进去看到的帧"没有差别。
- **标本页是纸 + 帧板**：上方一块 1920×1080 的帧板（元信息 + 标准形态），下方是状态带（`PRESETS` 逐档）与最小 HTML；两者在帧板外，不占 888 安全区。
- **每个组件一页**：一行元信息（层 · 标签 · 名字 · 上下页 · 序号）+ 该组件的标准形态。**单镜头**。
- 没有「成品」「用法」「解剖」——前两个是 DEMO 与叙事，第三个是调试信息，都不属于本层。
- **变体在状态带里逐档展示**（复用 `PRESETS`，数据件用短 fixture）；门禁仍逐条施加并比对像素，**每个预设必须产生可见差异**。
- 属性表在 `docs/reference.md`，由 registry 生成，与运行时同一份声明。
- 桌面 only；不提供移动布局。

## 10 · 一帧一个焦点

如果你有两个东西都想让人看，那是两帧。

内容装不下时，删内容，不缩字。这是这套库唯一愿意坚持的"约束"。

## 11 · 没有动效

库不描述动效。没有逐行淡入、没有打字机、没有 `vk.freeze()`，也没有时间轴。

**静止帧就是成品**：`vk shot` 出的那张图就是最终画面，动效在剪辑软件里做。
这条不是能力缺失，是边界——一旦库里带时间，它就不再是"一帧一个焦点"的画面语言，
而变成了一个播放器。

## 12 · 可寻址的讲解画布

5.0 的重心不是再加几张图，而是让**画面里的数据能被指到**：

- 锚点统一成 `#id@part:arg`：代码行、字符区间、内存格、字节、位、字段、汇编行/地址、时间线事件，以及几何锚点 `@point` / `@side` / `@region`（百分比，相对目标盒子）。
- 批注、连线、圈选、聚光、气泡都读同一套锚点；改内容时锚点跟着走，不靠手写坐标。
- `@field` / `@step` / `@cell` 都从 0 起；`current` 也 0 起。
- 覆盖层只画在包含块上，不占布局；隐藏的镜头没有盒子就不画。
- 代码/终端/diff/公式既可以从真实文件来，也可以放进 `<script type="text/plain" data-vk-source>`；两者只能选一个，仍然构建期编译、运行时零依赖。
- `vk-timeline` 是结构化形状，不读文件；年份轴不再靠 canvas 手摆。

这条协议服务的是"这里 / 左边 / 唯独这一行"——文案里最常见的指代，而不是新的叙事层。
时间仍然不在库里：多帧由作者写多页，`vk shot` 只负责其中一页。

## 13 · 属性词汇

一个概念一个名字；不再用四个名字说同一件事。

| 轴 | 属性 | 管什么 | 谁在用 |
|---|---|---|---|
| 形态 | `variant` | 这个形状长什么样 | edge / ring / spotlight / mark / rule / list / quote / diff / table / timeline |
| 刻度 | `scale` | 数值轴怎么映射 | bars |
| 窗 | `chrome` | 有没有窗头、哪种窗头 | window / code / term / diff / fig / tree / bytes / asm |
| 强度 | `emphasis` | 同一个形态有多重 | tag / pin / edge |
| 色调 | `tone` | 语义色 | 全部带语义的件 |
| 状态 | `state` | 作者手写条目的状态：`current` / `mark` / `ok` / `warn` / `err` | cells / bars / bits / timeline / list / table |
| 墨阶 | `ink` | 正文灰阶 | text / icon |
| 尺寸 | `size` | 字阶或图标档 | text / tag / callout / math / title / pin / icon |

单位也分工：`pad` / `gap` 只收 token（`2xs`…`3xl`），像素值写 `pad-px` / `gap-px`。
`x` / `y` 只在两种地方成立：`vk-canvas` 的子节点，或 `pin` / `ring` / `spotlight` 三个覆盖层；别的标签写了会在构建期报错。

索引基准只有两条：**源码行永远 1 起**（它指向真实文件），**数据下标永远 0 起**（格、字节、位、字段、步、事件、行）。
