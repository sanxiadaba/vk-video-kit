# 布局计划 · vk layout-plan

> 十轮设计结论 + 落地的实现。一句话：**锁词汇 / 解排版 / 存计划** —— 把"自由"从参数搬到结构。

## 1 · 三个误诊

| 抱怨 | 真相 |
|---|---|
| 属性太少，改不动 | 缺的是**"份"**：`vk-grid` 只有 `cols`，子项没有 `span`，2/3 + 1/3 写不出来，只能退回 `vk-canvas` 手摆像素 |
| 所以要开放样式 | 自由**全在错误维度**：`style`/`class` 从不被门禁看，`w`/`h` 像素随时可写——AI 一定走这两条路，然后一点点啃穿视觉系统 |
| 所以要像 antd 一样灵活 | antd 的灵活是给**人写页面**的；这里的甲方是**AI 出一帧**，目标函数不同：AI 要的是"表述力 ÷ 规则数"，不是主权 |

写页面的人需要主权；写帧的 AI 需要**封闭的词汇 + 会求解的编译器**。

## 2 · 三层

```
L0 词汇   锁死。五档字阶、4 个语义色、8 的倍数间距。AI 只能"选"，不能"调"。
L1 排版   求解。容器给份（cols/rows），子项占份（span），撑满用 fill。
          求解器只动布局维度：列数、比例、间距档、顺序。永不碰字号与对比度。
L2 证据   落盘。每次求解产出 plan.json —— 画面的 diff。
L3 教学   报错即文档。错误里带"你写了什么 / 该写什么 / 为什么"。
```

**关掉参数自由，才换来组合自由。** 破例的正确成本是**新增组件**，不是新增属性。

## 3 · API（已进库）

```html
<vk-grid cols="3" gap="lg" fill>
  <vk-code span="2" src="hello.c" lines="4-9"></vk-code>
  <vk-stack span="1" gap="md">…</vk-stack>
</vk-grid>
```

| 名字 | 位置 | 含义 |
|---|---|---|
| `cols` / `rows` | `vk-grid` | 切几份（1–6，闭集）。`rows` 会自动吃掉剩余高度——不等分就没有意义 |
| `span` | 任意块级子项 | 占几列，缺省 1；**父级必须是 `vk-grid`** |
| `row-span` | 任意块级子项 | 占几行；同样只在 `vk-grid` 里成立 |
| `fill` | 任意块级 | 吃掉剩余，不参与分份 |

两轴同构：容器声明份数（`cols` / `rows`），子项声明占比（`span` / `row-span`）。

### 被关掉的后门

| 后门 | 现在的行为 |
|---|---|
| `style=""` | 从 `GLOBAL_ATTRS` 删除 → **未知属性，构建期报错** |
| `w` / `h` | 只允许 `vk-canvas` 自己或它的子节点（坐标空间）；其它标签写了报错 |
| `span` / `row-span` 放错位置 | 父级不是 `vk-grid` → 构建期报错（浏览器会静默忽略 `grid-column` / `grid-row`） |
| `vk-img` 的 `w/h` | 从 API 面删除（本来就不生效，别教错） |

### 改名：`vk-code.span` → `vk-code.omit`

`span` 归布局。代码窗的"字符区间"改名 `omit`（`omit="4:9-12"`），一个概念一个名字。

## 4 · 容量是算得出来的

| 量 | 值 | 由来 |
|---|---|---|
| 正文行数 | **11 行** | 888 ÷ (52 × 1.5) |
| 一行汉字 | **32 字** | 1680 ÷ 52 |
| 窄栏（3 份取 1） | **10 字/行** | 528 ÷ 52 |

"放不下"在写之前就能算：`11 - 标题 3 - 代码 3 = 剩 5 行给要点`。

## 5 · 求解：不是裁判，是解法

装不下时先**自己改**。只动布局维度（`cols` / `gap`），在活页面上逐个试，量到能装下为止：

```json
"id": "10", "fits": true, "file": "frames/10.html",
"usage": { "inkH": 741, "ratio": 0.834, "lines": 9.5, "budget": 11 },
"solved": { "gridIndex": 0, "attr": "cols", "from": "2", "to": "1",
            "applied": true, "verified": true, "lines": 9.5 }
```

`applied: true` 意味着**已经写回文件**——plan 与产物同源，不是一张建议书。想只看不改：`--no-apply`；完全关掉：`--no-solve`。

单帧怎么改都不行，才升级到跨帧：

```json
"suggest": [{ "action": "split", "moveLines": 13, "to": null, "splitInto": 3,
              "why": "整套没有哪一帧接得住——按 24.1 行 ÷ 11 行算，这一帧要拆成 3 帧" }]
```

有帧接得住时是 `action: "move"` + 具体帧号；接不住才 `splitInto`。

四条设计要点：

1. **量墨水，不量盒子。** `fill` 会把容器撑满，量盒子得到的用量恒等于 1；必须量文字实际画到哪（`createRange` + `getClientRects`）。
2. **候选由作者给，变体由求解器试。** CJK 折行算不准，只有浏览器量得准；`cols` 从"少一列"开始试，因为格子越宽、折行越少。
3. **一致性强校验。** 写盘后再量一遍，`plan.fits` 与实测不一致就失败。
4. **只动布局，不动字。** 求解器永远不碰字号、对比度、语义色——那条线是护城河。

## 6 · 切片实测（`slice/`）

```
npm run slice                                 # build（严格）+ 求解 + 截图 + plan.json
node tools/box-tree.mjs slice/frames/07.html  # 打印盒子树
```

| 帧 | 结构 | 用量 | 结果 |
|---|---|---|---|
| 07 | `cols=3` · code `span=2` + 要点 `span=1` | 9.5 / 11 行 | ✓ 一次装下 |
| 08 | `cols=2` · 两窗各 `span=1` | 5.8 / 11 行 | ✓ 装下，偏空 |
| 09 | 2 栏版溢出 374px → 求解器在候选中改用 1 栏版 | 11.3 / 11 行 | ✓ 换文件 |
| 10 | 5 条事实塞进 2 栏 → 折成 10 行 | 9.5 / 11 行 | ✓ **自动改 `cols` 2→1 并写回** |
| 11 | 9 条事实，怎么改列都装不下 | 24.1 / 11 行 | ✗ → 拆成 3 帧 |

`10` 与 `11` 是一对对照：同一类内容，一个在单帧内可解（求解器自己动手），一个必须拆帧（求解器算出拆几帧）。

## 7 · 校验

- **严格模式默认开**：`vk build` 直接拒绝像素 `w/h`、`style`、错位 `span`。要迁就旧页才用 `--loose`。
- `span` / `rows` 是**语境属性**（`context: 'grid-child'` / `'bounded-height'`），契约测试跳过逐条探针——它们由构建期校验和单元测试覆盖。

### 报错即文档：三段式

每条错误按 `你写了什么 / 应该写什么 / 为什么` 组织（`src/shared/diag.mjs`）：

```
slice/frames/_bad.html:2 <vk-code> 的 w/h 是像素摆位
  你写了：w="900"
  应该写：要分栏用 <vk-grid cols="3"> 配子项 span="2"；要撑满用 fill
  为什么：像素值进不了容量检查，也进不了求解器——它只是把"摆不下"推迟到肉眼发现
```

第一行可 grep、可被编辑器点开；后三行是给 AI 的教案。已覆盖：未知属性、词表越界、数值越界、布尔误用、`x/y`、`w/h`、错位 `span`、行段格式。

## 8 · 工具

| 命令 | 作用 |
|---|---|
| `npm run slice` | 构建切片 + 求解 + 截图 + 写 `slice/plan.json` |
| `npm run plan -- <deck.json>` | 对任意 deck 出容量表、自动求解、跨帧建议 |
| `npm run box -- <page.html>` | 打印盒子树（排查"为什么它摆成这样"） |

| 开关 | 作用 |
|---|---|
| `--no-solve` | 只量不修，回到"裁判"模式 |
| `--no-apply` | 求解但**不写回文件**，只出建议（`solved.applied: false`） |
| `--dry` | 不截图 |

求解器只依赖 `deck.json`：`{ frames: [{ id, file, candidates? }] }`。候选是作者给的合法摆法，实测择优；候选都不行才自动改 `cols`。

## 9 · 存量迁移（已清零）

仓库里原本有 20 处 `w=`、13 处 `h=`、1 处 `style=`。处置方式：

| 原来 | 现在 |
|---|---|
| `vk-canvas` 子节点的 `x/y/w/h` | 保留（坐标空间本来就该有像素） |
| 标本页外层的 `<vk-box w="1400">` | `<vk-box class="spec-w">` + 作者 CSS |
| 缩略图 `<vk-stack h="352">` | `<a class="spec-card">` + CSS 定高 |
| 竖线 `style="height:240px"` | `<div class="spec-h240">` + `vk-rule fill` |
| `vk-img w/h` | 删除（从未生效） |

现在 `npm run build` **零警告**。

## 10 · 还没做

1. **预算前置**：现在是"先渲染再量"，理想是"写之前按内容行数分配帧"。难点是 CJK 折行不可静态预测，只能做粗估 + 事后校正。
2. **`area` 命名区域**：`span` + `row-span` 已经能表达"2 列 × 2 行"，但跨行跨列的组合仍要靠嵌套 `vk-grid`；真出现复杂版式再加。
3. **报错文案的英文与编辑器跳转**：现在只有中文，`file:line` 也只是一个字符串，没有可点击协议。
4. **求解器的搜索面**：现在只试 `cols`（≤18 次尝试），还没试 `gap`、`rows`、`span` 重分配；再往上要加"候选打分"而不是"第一个装得下就收"。
